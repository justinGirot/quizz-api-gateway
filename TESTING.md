# Gateway Testing Guide

This guide shows how to test that the API Gateway correctly routes requests to the authentication service and other backend services.

## Prerequisites

1. **Java 21** installed and `JAVA_HOME` configured
2. **Auth Service** running on port 8081 (optional - gateway will use fallback if not running)
3. **Gateway** running on port 8080

## Quick Start

### 1. Start the Gateway

```bash
# Set JAVA_HOME (Windows Git Bash)
export JAVA_HOME="/c/Program Files/Java/jdk-21"

# Start the gateway
./mvnw spring-boot:run
```

The gateway will start on port 8080 and show route configurations in the logs:
```
Configuring Auth Service route: /api/auth/** -> http://localhost:8081
Configuring Question Service route: /api/questions/** -> http://localhost:8082
Configuring Quiz Service route: /api/quizzes/** -> http://localhost:8083
```

### 2. Verify Gateway is Running

```bash
# Check health endpoint
curl http://localhost:8080/actuator/health

# Expected response:
# {"status":"UP","components":{...}}
```

## Testing Auth Service Routing

### Test 1: Basic Health Check (if auth service has /health endpoint)

```bash
curl -v http://localhost:8080/api/auth/health
```

**Expected outcomes:**
- **If auth service is running**: Returns 200 OK with health status
- **If auth service is down**: Returns 503 Service Unavailable (circuit breaker fallback)
- **Both cases**: Gateway adds `X-Correlation-ID` header

### Test 2: Test Any Auth Endpoint

```bash
# GET request
curl -v http://localhost:8080/api/auth/users

# POST request (login example)
curl -v -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"testuser","password":"testpass"}'

# With Authorization header
curl -v http://localhost:8080/api/auth/profile \
  -H "Authorization: Bearer your-token-here"
```

**What to look for:**
- Gateway should forward the request to `http://localhost:8081/api/auth/*`
- Response headers should include:
  - `X-Correlation-ID`: UUID generated by gateway
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `X-XSS-Protection: 1; mode=block`

### Test 3: Test CORS

```bash
# Preflight request
curl -v -X OPTIONS http://localhost:8080/api/auth/login \
  -H "Origin: http://localhost:5174" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: Content-Type,Authorization"
```

**Expected response headers:**
```
Access-Control-Allow-Origin: http://localhost:5174
Access-Control-Allow-Methods: GET,POST,PUT,DELETE,PATCH
Access-Control-Allow-Headers: Authorization,Content-Type,Accept,...
Access-Control-Allow-Credentials: true
```

### Test 4: Test Circuit Breaker Fallback

**When auth service is NOT running:**

```bash
curl -v http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"test","password":"test"}'
```

**Expected response (503 Service Unavailable):**
```json
{
  "timestamp": "2025-11-15T14:30:00",
  "status": 503,
  "error": "Service Unavailable",
  "message": "The authentication service is temporarily unavailable. Please try again in a few moments.",
  "service": "Auth Service",
  "circuitBreakerActive": true
}
```

### Test 5: Direct Fallback Endpoint

```bash
curl -v http://localhost:8080/fallback/auth
```

**Expected response:**
```json
{
  "timestamp": "2025-11-15T14:30:00",
  "status": 503,
  "error": "Service Unavailable",
  "message": "The authentication service is temporarily unavailable. Please try again in a few moments.",
  "service": "Auth Service",
  "circuitBreakerActive": true
}
```

### Check Circuit Breaker Status

```bash

curl http://localhost:8080/actuator/circuitbreakers

# Circuit breaker events
curl http://localhost:8080/actuator/circuitbreakerevents
```

### Check Gateway Logs

The gateway logs all requests with correlation IDs:


## Common Scenarios

### Scenario 1: All Services Running
- **Auth service on 8081**: ✅ Running
- **Question service on 8082**: ✅ Running
- **Quiz service on 8083**: ✅ Running
- **Result**: All requests routed successfully, circuit breakers CLOSED

### Scenario 2: Auth Service Down
- **Auth service on 8081**: ❌ Down
- **Result**:
  - First few requests may timeout
  - Circuit breaker OPENS after failure threshold (50%)
  - Subsequent requests immediately return fallback response (503)
  - After 30 seconds, circuit breaker enters HALF-OPEN state
  - 3 test requests sent to check if service recovered

### Scenario 3: Network Delay
- **Auth service responding slowly** (>2 seconds)
- **Result**:
  - Requests marked as "slow calls"
  - After 50% slow calls, circuit breaker OPENS
  - Time limiter kicks in at 3 seconds
  - Fallback response returned

## Testing with Frontend

If you have the Quizz frontend running:

1. **Start frontend** (default port: 5174)
2. **Start gateway** (port 8080)
3. **Start auth service** (port 8081)
4. **Configure frontend** to use gateway URL:
   ```javascript
   const API_BASE_URL = 'http://localhost:8080';
   ```
5. **Test authentication flow**:
   - Login page should send POST to `http://localhost:8080/api/auth/login`
   - Gateway routes to `http://localhost:8081/api/auth/login`
   - CORS headers allow the request from frontend origin

## Troubleshooting

### Issue: "Connection refused"
**Cause**: Target service (auth service) is not running
**Solution**:
- Start the auth service on port 8081
- Or verify the fallback mechanism is working (should return 503)

### Issue: "CORS error in browser"
**Cause**: Origin not allowed
**Solution**: Check `application.yml` CORS configuration:
```yaml
cors:
  allowed-origin-patterns:
    - "http://localhost:[*]"
```

### Issue: "404 Not Found"
**Cause**: Route path doesn't match
**Solution**: Verify route configuration in `application.yml`:
```yaml
gateway:
  routes:
    auth-service:
      path: "/api/auth/**"  # Must match request path
```

### Issue: "Circuit breaker always open"
**Cause**: Too many failures, circuit breaker protecting backend
**Solution**:
1. Check backend service is healthy
2. Wait 30 seconds for half-open state
3. Check circuit breaker config in `application.yml`

## Configuration Validation

Verify your current configuration:

```bash
# Check active routes
curl http://localhost:8080/actuator/health | jq

# Check application properties
cat src/main/resources/application.yml | grep -A 10 "gateway:"

# Verify Eureka is disabled (if using direct URLs)
cat src/main/resources/application.yml | grep -A 5 "eureka:"
```

## Performance Testing

### Simple load test with curl (Windows Git Bash)

```bash
# Send 100 requests and measure response times
for i in {1..100}; do
  curl -w "%{time_total}\n" -o /dev/null -s http://localhost:8080/api/auth/health
done | awk '{s+=$1; count++} END {print "Average: " s/count " seconds"}'
```

### Using Apache Bench (if installed)

```bash
# 1000 requests, 10 concurrent
ab -n 1000 -c 10 http://localhost:8080/api/auth/health
```
